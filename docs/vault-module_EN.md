# Vault Module — Keeper Secrets Manager Integration

[← Back to Documentation](../README.md#documentation)

## Overview

The Vault module integrates Keeper Secrets Manager (KSM) into Guacamole, enabling automatic credential retrieval and injection. Sensitive information like passwords in connection configurations no longer needs to be hardcoded — instead, it is dynamically fetched from KSM when a connection is established.

**Key Features:**
- Fetch secrets from Keeper Secrets Manager
- Automatic credential injection via `${TOKEN}` replacement mechanism
- Custom token mapping paths supported
- In-memory cache for performance optimization (5-second TTL)

## Configuration

### Enabling the Vault Module

```yaml
guacamole:
  vault:
    ksm:
      enabled: true
```

### KSM Connection Configuration

```yaml
guacamole:
  vault:
    ksm:
      enabled: true
      config:
        ksm-config: "keeper://<base64-encoded-config>"
        allow-unverified-cert: false
```

| Property | Required | Default | Description |
|----------|----------|---------|-------------|
| `guacamole.vault.ksm.enabled` | Yes | `false` | Enable KSM Vault |
| `config.ksm-config` | **Yes** | — | Base64-encoded KSM config (generated by Keeper Commander CLI) |
| `config.allow-unverified-cert` | No | `false` | Whether to allow unverified SSL certificates |

**Generate KSM Config:**
```bash
keeper commander client --config --output=base64
```

## Token Mapping

Create the token mapping file: `~/.guacamole/ksm-token-mapping.yml`

```yaml
# Format: TOKEN_NAME: "secret path in KSM"
USERNAME: "production/server-01/username"
PASSWORD: "production/server-01/password"
CONNECTION_HOSTNAME: "production/server-01/hostname"
CONNECTION_USERNAME: "production/server-01/username"
```

### Supported Tokens

| Token | Description | Usage Example |
|-------|-------------|--------------|
| `${USERNAME}` | Current username | Connection username field |
| `${CONNECTION_NAME}` | Connection display name | Hostname parameter |
| `${CONNECTION_ID}` | Connection database ID | Custom attributes |
| `${CONNECTION_HOSTNAME}` | Connection hostname | VNC/RDP host field |
| `${CONNECTION_USERNAME}` | Connection username | SSH user field |
| `${CONNECTION_GROUP_NAME}` | Parent group name | For tagging |
| `${CONNECTION_GROUP_ID}` | Parent group database ID | For filtering |

### Using Tokens in Connection Configuration

```
Connection Name: Production Server
Hostname:  ${CONNECTION_HOSTNAME}
Username:  ${USERNAME}
Password:  ${PASSWORD}
```

When a connection is established, `${USERNAME}` is replaced with the actual value from `production/server-01/username` in KSM.

## Processing Flow

### Startup Phase

```
Spring Boot starts
  → KsmAuthenticationAutoConfiguration loads
  → Creates KsmClient, KsmSecretService, KsmRecordService beans
  → Registers KsmAuthenticationProvider
```

### User Login

```
User submits login → KsmAuthenticationProvider → Authentication succeeds
  → Creates VaultUserContext
  → Loads token mapping
```

### Connection Access

```
User clicks connection
  → VaultUserContext.getConfiguration()
  → Scans configuration for ${TOKEN} patterns
  → For each token:
      → KsmSecretService.getValue(token, path)
        → Check cache (5-second TTL)
        → Cache miss → KsmClient.getSecret(path)
        → Cache hit → Return cached value
      → Replace ${TOKEN} with secret value
  → Return resolved configuration
```

## Error Handling

### Missing KSM Configuration

```
ERROR: Property ksm-config is required.
```

**Cause:** `config.ksm-config` not configured in `application.yml`.

**Solution:**
```yaml
guacamole:
  vault:
    ksm:
      config:
        ksm-config: "keeper://<base64-encoded-config>"
```

### Token Mapping File Not Found

```
WARN: Token mapping file not found: ksm-token-mapping.yml
```

**Cause:** The `~/.guacamole/ksm-token-mapping.yml` file does not exist.

**Solution:** Create the file and fill in the corresponding token mappings.

### KSM Connection Failure

```
ERROR: Failed to connect to Keeper Secrets Manager
```

**Cause:** Network issues or invalid KSM configuration.

**Solution:**
- Check network connectivity to the KSM server
- Verify `ksm-config` is valid and not expired
- Check firewall settings

### Token Not Replaced

```
WARN: Token "${USERNAME}" not replaced
```

**Cause:** Token name has no corresponding entry in the mapping file, or the secret path does not exist in KSM.

**Solution:** Check the token mapping file and confirm the secret path exists in KSM.

## Troubleshooting

### Application Startup Failure

**Symptom:** Bean creation error at startup.

**Possible Causes:**
- Circular dependency between Vault beans
- Invalid `ksm-config` format

**Solution:**
- Check detailed error information in logs
- Verify `ksm-config` is correctly Base64-encoded
- Ensure all Vault dependencies are on the classpath

### Token Not Replaced

**Symptom:** Connection uses literal `${TOKEN}` text instead of resolved values.

**Possible Causes:**
- Token mapping file missing or incorrectly formatted
- Token name case mismatch
- Secret path not found in KSM

**Solution:**
- Check token mapping file location: `~/.guacamole/ksm-token-mapping.yml`
- Verify token names match exactly (case-sensitive)
- Test secret retrieval directly via KSM API

### Connection Failure After Enabling Vault

**Symptom:** Previously working connections fail after enabling Vault.

**Possible Causes:**
- KSM inaccessible (network/credential issues)
- Secrets have been changed or revoked
- KSM rate limiting

**Solution:**
- Check KSM connectivity and credentials
- Verify secret values in KSM are correct
- Check for rate limiting or service availability
